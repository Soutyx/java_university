# Решения

1. Проверки в `ApprovalRouter.route` расположены по приоритету: персональные данные, риск, сумма, срочность. Первый подходящий маршрут сразу возвращается. Срочность поэтому не может пропустить проверку безопасности.

2. Порог риска вычисляется из `RISK_PRIORITY_PERCENT = 30`: `500000 * 30 / 100 = 150000`. Взята та же трактовка, что и в примере репозитория. Число 150000 в методах не дублируется.

Вариант 5. В PDF не объяснено, что означает параметр «приоритет риска — 30». Процент взят по примеру; при этой трактовке HIGH ниже 150000 не требует директора. Общее правило PDF требует директора при любом HIGH. Для него в `requiresDirector` нужно оставить только сравнение риска с `RiskLevel.HIGH` и обновить ожидания тестов.
